# 整数范围分析

整数范围分析（Integer Range Analysis）为程序点上的整数 value 推导一个安全的取值集合近似，用于化简比较、消除不可能分支、证明除数非零、辅助边界检查和循环优化。

最简单的抽象是区间：

```text
x in [min, max]
```

但机器整数具有固定位宽、wrap、符号解释和 poison/overflow 语义，所以不能直接把它当作无限精度数学整数区间。

## 1. 抽象解释视角

范围分析可以看成 abstract interpretation：

- concrete domain：所有可能的机器整数集合；
- abstract domain：interval、wrapped interval、known bits 等有限表示；
- transfer function：抽象执行每种 instruction；
- join：合并多条 CFG 路径的 facts；
- fixed point：处理循环。

分析必须 sound：抽象范围可以比真实集合更大，但不能漏掉任何真实可能值。

## 2. 基本 Interval Domain

对有符号 `w` 位整数，完整范围是：

$$
[-2^{w-1}, 2^{w-1}-1].
$$

常见抽象元素：

- `bottom`：没有可达 concrete value；
- singleton `[c,c]`：确定常量；
- 普通区间 `[l,u]`；
- `top`：任意该位宽 value。

Join 通常取覆盖两者的最小区间：

```text
join([0,3], [8,10]) = [0,10]
```

这会丢失中间 `[4,7]` 不可能的事实，体现 interval domain 的精度限制。

## 3. Signed 与 Unsigned

相同 bit pattern 有两种顺序解释。例如 i8 的 `0xff`：

- unsigned 为 255；
- signed 为 -1。

比较和除法必须使用相应 signedness。一个 unsigned range 转为 signed range 时可能不再是单一连续区间。

分析接口应明确：

- 区间采用 signed 还是 unsigned 顺序；
- 是否同时维护两种视图；
- cast、compare 和 shift 如何解释高位。

## 4. Wrapped Interval

机器整数模 $2^w$ 运算。普通线性区间难以表示跨越最大值回绕的集合，例如 i8：

```text
[250, 255] U [0, 5]
```

Wrapped interval 可以在模环上表示这种集合；另一种做法是退化为 `top`。前者更精确，后者实现简单。

如果 IR 的某条运算带 `nuw`/`nsw`，发生 wrap 可能产生 poison 或属于不允许路径，而不是普通模运算。Transfer function 必须遵守具体 IR 语义。

## 5. Transfer Function

### Add / Sub

数学整数下：

```text
[a,b] + [c,d] = [a+c, b+d]
```

机器整数下还要处理可能 overflow：

- wrapping semantics 可形成 wrapped interval；
- no-wrap 无法证明时可能退化；
- poison semantics 下要区分 value range 与程序定义域。

### Mul

候选端点为：

```text
a*c, a*d, b*c, b*d
```

取最小最大值，但符号、overflow 和位宽会增加复杂度。

### Div / Rem

必须处理：

- divisor 是否可能为 0；
- signed `MIN / -1`；
- truncation direction；
- remainder 的符号规则；
- unsigned 与 signed 指令差异。

若 divisor range 排除 0，可以证明除法不会因除零失败；这也可支持安全代码移动。

### Shift

需要知道：

- shift amount 合法范围；
- logical 与 arithmetic shift；
- 目标对超范围 shift 的语义；
- 左移 overflow/poison 规则。

### Bitwise

普通 interval 对 `and/or/xor` 精度较弱。Known-bits domain 更擅长表示每一 bit 必为 0、必为 1 或未知。

## 6. Known Bits 与 Congruence

### Known Bits

维护：

```text
knownZeroMask
knownOneMask
```

可证明：

- 非负；
- 某些 alignment；
- `x & mask` 的范围；
- 高位符号模式；
- 某些 compare 结果。

### Congruence

表示：

$$
x \equiv r \pmod m.
$$

例如地址按 16 字节对齐：

```text
x ≡ 0 (mod 16)
```

它对 alignment、stride、divisibility 和 [[SCEV]] 推理很有帮助。Interval、known bits 与 congruence 可以组成 product domain，相互增强。

## 7. Range Fact 不只是一对端点

更丰富的 fact 可能包含：

- interval；
- known bits；
- nonzero；
- power-of-two alignment；
- 与某个 value 的关系；
- no-overflow 条件；
- provenance 或 materializability。

要区分：

- value 的全局保守范围；
- 某个 block 入口的范围；
- 某条 CFG edge 上的范围；
- 某个 use context 下的范围。

## 8. Branch Refinement

```c
if (x < 10) {
    use(x);
}
```

在 true edge 上可得到：

```text
x <= 9
```

在 false edge 上：

```text
x >= 10
```

若进入 branch 前已有 `x in [0,100]`，则：

```text
true edge:  x in [0,9]
false edge: x in [10,100]
```

对 `x == c`、`x != c`、unsigned compare、两个变量之间的 compare，也可以产生 edge facts。`!=` 常导致非凸集合，例如 `[0,c-1] U [c+1,n]`，单一区间可能无法精确表示。

## 9. Phi 与路径合并

```text
P1: x1 in [0,3]
P2: x2 in [8,10]
B:
    x = phi [x1,P1], [x2,P2]
```

在 `B` 中，普通 interval join 得：

```text
x in [0,10]
```

但若查询特定 edge：

```text
P1 -> B: x 选择 [0,3]
P2 -> B: x 选择 [8,10]
```

路径敏感消费者可以利用更精确的 edge fact；一旦多路径合流且不再区分来源，就只能保留共同安全近似。

## 10. 关系分析

Interval 适合描述单 value 范围，却不擅长表达变量间关系：

```text
x < y
x == y + 1
x - y in [0,3]
```

Relational domains 包括：

- difference constraints / DBM；
- octagons；
- polyhedra；
- equality/congruence classes；
- predicate sets。

精度越强，计算与存储成本越高。[[CVP]] 常利用支配条件和关系事实做路径相关化简，而不一定构建完整多面体域。

## 11. 循环与 Fixed Point

循环造成循环依赖方程：

```text
header range
-> body transfer
-> latch range
-> backedge join header
```

直接迭代可能需要很多轮，甚至在无限高度域上不终止。常用方法：

### Widening

当边界持续扩张时快速提升到更宽范围，例如把上界扩大为 `+∞/type max`，保证收敛。

### Narrowing

在 widening 得到不动点后，再做有限轮精化，收回过度保守部分。

### 归纳变量识别

借助 [[SCEV]] 或 header Phi recurrence，直接推导：

```text
i = start + k*step, 0 <= k < tripCount
```

通常比纯 interval fixed-point 更精确。

## 12. 跨过程摘要

函数可以维护参数和返回值摘要：

```text
ParamRange(f, i)
ReturnRange(f)
```

调用点把 actual argument ranges 合并到 parameter summary，callee 的 return summary 再传播回 caller。

需要保守处理：

- 外部可见函数的未知 callers；
- 递归调用的 fixed point；
- 间接调用；
- 全局/内存 effects；
- 不同 callsites 的路径相关信息。

这与 [[IPSCCP]] 的跨过程常量传播相似，但 range lattice 比单一 constant 更丰富。

## 13. 可进行的化简

### Compare Folding

```text
x in [0,9]
x < 10 -> true
x < 0  -> false
```

### Branch Pruning

若条件范围只能为 true 或 false，可以删除不可能 edge，并进一步简化 Phi 和不可达区域。

### Div/Rem Simplification

若已知：

```text
0 <= x < d
```

则：

```text
x / d = 0
x % d = x
```

仍需确认 signedness、`d > 0` 和机器语义。

### Bounds Check Elimination

```text
0 <= i < length
```

可证明相应数组访问在界内。若 pointer provenance、对象大小或 overflow 语义不明，仅有整数范围可能还不够。

### Safe Speculation

证明 divisor 非零、shift amount 合法或地址范围安全，可以支持代码移动和 [[GVN、FRE 与 PRE|PRE]] 插入。

## 14. 与 SCCP、CVP、Jump Threading 的关系

### [[IPSCCP|SCCP / IPSCCP]]

SCCP 主要传播 `unknown / constant / overdefined` 与 executable edges；range analysis 用更丰富的集合代替单一 constant。

### [[CVP]]

CVP 强调使用控制流上下文中的 predicate/关系化简当前 operation。Range analysis 可以提供这些 facts，但二者不必是同一个实现。

### [[Jump Threading]]

若某条件只在特定 predecessor edge 上确定，jump threading 可以把该 edge 直接连接到确定 successor。必须保留 edge context，不能把局部事实提升成整个 block 的全局事实。

### [[SCEV]]

SCEV 擅长表达跨迭代递推和 trip count；range analysis 擅长回答程序点上的值集合。二者可以相互提供边界和 no-wrap 证据。

## 15. Materializable Constant 与事实常量

分析证明某 value 在某个 context 中是 singleton，并不总表示可以无条件用 constant 替换所有 uses。

要考虑：

- 事实是否只在某条 edge 或 block 中成立；
- value 是否携带 poison/undef 语义；
- 替换是否越过 freeze 或其他语义边界；
- constant 的类型和位宽是否一致。

因此可以区分：

- singleton range：在当前上下文只可能有一个数值；
- materializable singleton：可以安全物化并替换的常量。

## 16. 精度与成本权衡

提高精度的方法包括：

- wrapped/disjoint intervals；
- edge-sensitive facts；
- relational domain；
- context sensitivity；
- path splitting；
- 与 SCEV/known bits/congruence 组合。

代价是更多状态、更慢 join、更复杂 fixed point 和路径爆炸。实用实现通常选择少量可复用的强 facts，并在超出预算时保守退化。

## 17. 常见误区

- 把机器整数当成无限精度整数。
- 混淆 signed 与 unsigned range。
- 加减乘的端点计算溢出后仍当成精确区间。
- 除法范围忽略 0 和 `MIN / -1`。
- Shift amount 超范围语义未建模。
- 将某条 edge 上的事实推广到整个 merge block。
- Phi join 只选一个 predecessor 的范围。
- `x != c` 被错误表示为一个不包含 `c` 的普通连续区间。
- 分析得到 singleton 就无条件替换所有 uses。
- Widening 结果被当成精确上界。
- 无法证明范围时给出乐观窄区间，而不是退化为 top。

## 18. 关系速记

```text
Instruction semantics
  -> transfer functions

CFG edges / branch predicates
  -> edge-sensitive refinement

Phi / joins / loops
  -> fixed point + widening/narrowing

Interval + known bits + congruence + relations
  -> compare folding / branch pruning / bounds proof
  -> [[CVP]] / [[Jump Threading]] / [[SCEV]] / [[GVN、FRE 与 PRE]]
```
