# 指令选择与合法化

Instruction Selection（指令选择）把较抽象的中间表示映射为目标机器指令或目标相关机器 IR。Legalization（合法化）则确保操作类型、立即数、地址形式、寄存器约束和伪指令状态满足下一阶段或最终 ISA 的要求。

二者不是“把 opcode 名字一一替换”。一条目标指令可能覆盖多个 IR 节点，一个 IR 操作也可能展开成多条机器指令。

## 1. 指令选择的输入与输出

输入通常是：

- SSA values；
- target-independent arithmetic/control/memory operations；
- 显式 CFG；
- type、layout、alignment 与 calling-convention 语义。

输出通常仍是 Machine SSA：

- target opcodes；
- virtual registers；
- target immediates；
- machine basic blocks；
- 尚待处理的 call、stack、branch 等 pseudos。

寄存器分配详见 [[寄存器分配]]。

## 2. Lowering 通常创建新表示

一种清晰实现是创建新的 target module/function/block/instruction，并维护映射：

```text
old function -> new function
old block    -> new block
old value    -> new value
```

这样可以：

- 保留输入 IR 不变；
- 明确 target IR 的合法 opcode 集合；
- 避免同一 instruction 在过渡期间同时具有两套语义；
- 集中处理 old→new operand 映射。

构建顺序需要保证 forward references 可解析。对 SSA，可以先创建 blocks 和 Phi results，再 lowering 普通 instructions，最后连接 Phi incoming edges。

## 3. Tree、DAG 与 Graph Pattern

### Tree Pattern Matching

把 expression tree 覆盖为目标 instruction patterns，例如：

```text
add(x, mul(y, 4))
```

可能匹配带 shift/add 的组合。

### DAG Pattern Matching

SSA expression 可能有共享子表达式，不再是树。选择器必须避免重复计算被多个 users 共享的节点，或明确决定何时允许 duplicate/rematerialize。

### Graph Pattern

Compare 与 branch、address calculation 与 load/store、multiply-add 等会跨多个 IR nodes 形成 pattern。匹配时要检查 intermediate result 是否还有其他 uses，否则融合会丢失值。

## 4. Rule Ordering

Rule-driven selector 通常按顺序尝试：

```text
更具体、收益更高的融合规则
-> immediate forms
-> zero-specialized forms
-> generic target operations
-> fallback expansion
```

如果 generic rule 先匹配，specialized rule 永远不会触发。若多个规则都合法，简单的“first match”还可能错过更便宜方案；更复杂系统会用 dynamic programming 或 cost model 选择最低成本 cover。

Rule 至少需要描述：

- pattern；
- legality predicate；
- emitted instructions；
- result mapping；
- consumed nodes/uses；
- estimated cost。

## 5. Immediate Selection

很多 ISA 为常用算术提供立即数形式：

```text
add register, register, imm
```

选择时要检查：

- immediate 位宽；
- signed/unsigned encoding；
- 是否要求对齐或特定位模式；
- 对常量取负是否溢出；
- 32-bit 与 64-bit 指令的结果扩展语义。

例如把 `x - C` 转为 `x + (-C)` 时，若 `C` 是最小有符号整数，`-C` 在同位宽下不可表示，不能直接应用。

超范围 constant 可能需要：

- 多条 `lui/addi` 类指令；
- constant pool load；
- materialize 到 register 再运算。

## 6. Compare + Branch Fusion

抽象 IR 常先产生 boolean：

```text
c = icmp.lt x, y
br c, T, F
```

若目标 ISA 支持直接条件分支，且 `c` 没有其他 uses，可以选择：

```text
blt x, y, T
j F
```

若 compare result 还被普通指令使用，就不能只生成 branch；可能需要同时 materialize boolean，或放弃融合。

还要处理：

- predicate 反转；
- true/false successor 交换；
- fallthrough 选择；
- signed/unsigned compare；
- floating-point unordered 语义。

## 7. Addressing Mode Selection

Load/store 常支持：

```text
load offset(base)
```

因此：

```text
p = base + offset
x = load p
```

在 `p` 只为该访存使用、offset 可编码且语义一致时，可以折叠为单条 memory instruction。

地址匹配必须保留：

- access width；
- signed/zero extension；
- alignment；
- address space；
- base register class；
- immediate 范围；
- pointer arithmetic 的位宽。

复杂 GEP 通常先规约成 base + byte offset，再选择目标 addressing mode。

## 8. Multi-Instruction Expansion

目标 ISA 可能没有某个 IR operation：

- 大常量除法；
- 64-bit operation 在 32-bit target 上；
- floating-point conversion；
- min/max 或 rotate；
- 某些 atomic operation。

Selector 或 legalizer 需要展开为 instruction sequence。展开时要考虑：

- 精确的 overflow、rounding 与 exception 语义；
- temporary values；
- target feature availability；
- sequence cost；
- 是否调用 runtime helper。

## 9. Legalization 的维度

### Type Legalization

把目标不支持的 value type 拆分、扩展或转换。例如在只原生支持 32-bit integer 的目标上实现 i64。

### Operation Legalization

把目标没有的 operation 展开成合法序列或 library call。

### Immediate Legalization

把超出编码范围的 immediate materialize 到 register，或拆为多条指令。

### Address Legalization

当 stack/frame/global offset 无法直接编码时，先用 scratch register 构造完整地址。

### Register-Constraint Legalization

满足特定指令要求的 fixed registers、register pairs 或 operand ties。

### Control-Flow Legalization

处理远跳、条件分支范围、fallthrough 和目标要求的 block layout。

## 10. Pre-RA 与 Post-RA Legalization

### Pre-RA Legalization

在寄存器分配前完成适合 virtual-register 形式的展开：

- 不支持的 operation；
- 大部分 immediate；
- 明确 use/def 和 fixed constraints；
- 使 allocator 看见真实寄存器压力。

### Post-RA Legalization

分配后才能确定的情况包括：

- 最终 stack/frame offsets；
- physical-register-specific constraints；
- large frame address；
- branch distance；
- 需要保留已分配 registers 的 scratch sequence。

Post-RA 若需要新 temporary，不能随意创建普通 virtual register。通常使用预留 scratch、scavenging 或受控 spill。

## 11. Pseudo Instruction 是阶段协议

Pseudo 不只是汇编语法糖，它保存“目前还不能决定”的信息。

常见 pseudo：

- call pseudo：保留参数和返回值的 SSA 关系；
- return pseudo：等待返回寄存器物化；
- stack-slot reference：等待 frame layout；
- frame-size reference：等待最终栈帧大小；
- combined branch/jump：等待 block layout 和 fallthrough；
- large constant/address pseudo：等待最终 expansion 策略。

每类 pseudo 都应有明确生命周期：

```text
谁产生
-> 哪些阶段允许存在
-> 谁消费/展开
-> 最迟何时必须消失
```

Pseudo 若过早展开，会丢失全局决策机会；若过晚保留，最终发射阶段可能没有足够上下文处理。

## 12. Integer Width 与扩展语义

目标 ISA 常区分：

- full-width integer operation；
- word operation；
- sign-extending load；
- zero-extending load；
- pointer-width arithmetic。

例如 64-bit ISA 上的 32-bit `addw` 可能把低 32 位结果符号扩展到 64 位。这不等于普通 64-bit `add`。

选择器必须明确：

- operand 的逻辑位宽；
- result 高位是截断、符号扩展还是零扩展；
- compare 按 signed 还是 unsigned；
- pointer arithmetic 是否使用 pointer width；
- bitcast 与数值转换的区别。

## 13. Calling Convention Lowering

Call lowering 需要把抽象参数、返回值与 ABI locations 对接：

- integer/floating parameters 使用不同 register banks；
- 寄存器参数耗尽后落栈；
- return value 位于固定 register；
- variadic function 可能有额外规则；
- call 隐式 clobber caller-saved registers；
- tail call 需要满足栈帧和参数布局约束。

一种做法是先保留带 SSA operands 的 call pseudo，让 [[寄存器分配]] 统一处理 fixed uses/defs 和跨 call liveness，再物化实际 moves 与 stack arguments。

## 14. Block Layout 与 Branch Expansion

机器 CFG 的两个 successors 不一定都需要显式 jump。若一个 successor 是布局上的下一块，它可以作为 fallthrough。

因此 branch expansion 往往要等 block layout 确定后进行：

```text
if cond goto T else F
```

可选择：

```text
bcond T
fallthrough F
```

或反转条件：

```text
bnotcond F
fallthrough T
```

选择应考虑 branch probability、编码范围和目标预测习惯。

## 15. Selection Cost 不只看指令条数

较短 sequence 不一定更快。Cost 还包括：

- latency 与 throughput；
- instruction size；
- register pressure；
- live-range extension；
- use of fixed/scratch registers；
- macro-fusion；
- memory addressing modes；
- critical-path length；
- block frequency。

例如把多个等价表达式复用成一个较早 definition，可能减少算术，却延长 live range 并造成 spill。指令选择与 [[寄存器分配]] 必须放在同一成本链条中理解。

## 16. 最终发射的边界

汇编发射应尽量是序列化终点，而不是继续做复杂语义决策。到最终发射前通常应满足：

- 只有合法目标 opcodes；
- operands 已是 physical registers、合法 immediates、symbols 或已解析 stack addresses；
- 不再有未展开 pseudos；
- branch targets 与 block layout 确定；
- data layout、alignment 和 sections 已确定。

若发射器仍需猜测 value type、分配 scratch 或修复 CFG，阶段边界通常过晚。

## 17. 常见错误

- Generic rule 抢先匹配，使 specialized rule 永远不可达。
- 融合 intermediate node 时忽略它还有其他 uses。
- Immediate 取负或截断发生溢出。
- 把 32-bit word operation 当成普通 64-bit operation。
- 地址折叠丢失 access width、alignment 或 extension 语义。
- Pseudo 没有明确的生产者和消费者。
- Post-RA 新建 virtual temporary。
- Stack offset 未知时过早展开地址。
- Branch layout 未定时固定 fallthrough。
- 只按静态 instruction count 选 pattern，忽略 register pressure。

## 18. 关系速记

```text
Target-independent SSA IR
  -> pattern matching / covering
  -> target Machine SSA + pseudos
  -> pre-RA legalization
  -> [[寄存器分配]]
  -> stack/call/branch materialization
  -> post-RA legalization
  -> final machine instructions / assembly
```
