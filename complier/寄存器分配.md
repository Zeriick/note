# 寄存器分配

寄存器分配（Register Allocation，RA）把数量近乎无限的虚拟寄存器映射到数量有限的物理寄存器，并在容量不足时决定在哪里 spill、reload、split 或 rematerialize。

它不是简单的“给每个 value 选一个寄存器”。真正问题是：在每个程序点，为所有同时活跃的 values 选择互不冲突且满足指令、调用约定和寄存器类别约束的位置，并控制动态移动与访存成本。

## 1. 虚拟寄存器与物理寄存器

指令选择之后，机器 IR 常仍使用 virtual registers：

```text
v3 = add v1, v2
```

分配后变为物理位置：

```text
a0 = add s1, t0
```

若没有足够寄存器，value 的一部分生命周期可能位于栈槽：

```text
store v -> spill_slot
...
v2 = load spill_slot
```

同一个 value 不必在整个生命周期中固定处于一个位置。Live-range splitting 允许它在不同区段使用不同寄存器或栈槽。

## 2. Register Class 与 Bank

物理寄存器通常分为不同 classes/banks：

- General-Purpose Register（GPR，通用整数寄存器）；
- Floating-Point Register（FPR，浮点寄存器）；
- vector/predicate/special registers；
- 某些指令限定的子寄存器或偶数对齐寄存器。

Value 的类型、指令约束和 ABI 决定它可以放入哪些寄存器。不同 bank 之间移动可能需要专门指令，不能把所有物理寄存器视为同一个无类型集合。

## 3. Liveness

一个 value 在程序点 live，表示它当前值可能在未来某条路径上被使用，且在使用前没有被重新定义。

对 basic block `B`，经典方程为：

$$
LiveOut(B)=\bigcup_{S\in succ(B)}LiveIn(S),
$$

$$
LiveIn(B)=Use(B)\cup(LiveOut(B)-Def(B)).
$$

迭代到不动点可得到块级活跃性，再反向扫描 block 内 instructions 得到程序点级 liveness。

### Phi 的边语义

```text
B:
    x = phi [a, P1], [b, P2]
```

`a` 只在 `P1 -> B` 边上 live，`b` 只在 `P2 -> B` 边上 live。若把所有 Phi operands 都当作在 `B` 入口同时使用，会制造虚假重叠和不必要 spill。

SSA 与 edge use 详见 [[构造|SSA 构造与维护]]。

## 4. Program Point 与 Live Range

为了表示“定义前、定义后、使用前、使用后”等位置，分配器通常给程序建立线性编号：

```text
block entry
inst use positions
inst def positions
inst end
block exit
```

必须区分：

### Value Lifetime

Value 从 definition 到所有 reachable uses 的语义生命周期。

### Live Interval

把 value 的活跃点投影到线性程序顺序后得到的区间集合。

### Live Segment

一个连续的半开区间：

```text
[start, end)
```

由于 CFG 分支和 liveness holes，一个 value 可对应多个不连续 segments。把它粗暴包成从最早 definition 到最晚 use 的单一区间，会制造大量假冲突。

### Live Bundle

若多个 segments 因 copy coalescing、Phi 或其他关系希望共享位置，可以组成 bundle 一起分配。Bundle 是分配决策单位，不一定等同于单一 SSA value。

## 5. Interference

若两个 values 在某个程序点同时 live，且不能共享同一物理寄存器，则它们 interference。

### Interference Graph

节点代表 live ranges，边代表冲突。Graph coloring register allocation 把寄存器分配转为图着色问题。最小着色是 NP-complete，因此实际算法使用 simplify、coalesce、freeze、spill 等启发式。

### Live Interval Matrix

线性扫描或 greedy allocator 常直接维护“每个物理寄存器已占用哪些 live segments”，通过区间重叠查询冲突，不必显式构造完整 interference graph。

## 6. 三类典型分配算法

### Graph Coloring

优点：全局视角强，能自然表达 interference 与 coalescing。缺点：实现复杂，构图和启发式成本较高。

### Linear Scan

按 live interval 起点排序，维护 active intervals，快速选择寄存器或 spill。编译速度好，常用于 JIT；处理 holes、fixed constraints 和高质量 splitting 时会逐渐复杂。

### Greedy Allocation

按 priority 从队列取 live range/bundle，尝试：

```text
空闲寄存器
-> eviction
-> splitting
-> spilling
```

它便于结合 frequency、hints、rematerialization 和局部 split 策略，是现代优化编译器常见方向。

## 7. Fixed Constraints 与 Register Hints

### Fixed Constraint

硬约束，不能违反。例如：

- 函数返回值必须位于 ABI 指定寄存器；
- 除法使用固定 dividend/result registers；
- shift count 必须位于特定寄存器；
- inline assembly clobber 指定 registers；
- call 在某些程序点破坏 caller-saved registers。

Fixed ranges 可看作物理寄存器已经被预占用的 live segments。

### Hint

软偏好，例如：

- copy 两端希望 coalesce；
- 函数参数希望沿用 ABI incoming register；
- Phi 相关 values 希望使用同一寄存器；
- 某条指令有更便宜的 preferred register。

Hint 只能影响候选顺序或成本，不能覆盖真实冲突。

## 8. Calling Convention 与 RegMask

Call 通常隐式读写一组物理寄存器：

- 参数寄存器是 fixed uses；
- 返回值寄存器是 fixed defs；
- caller-saved registers 可能被 clobber；
- callee-saved registers 若被函数使用，需要保存恢复。

跨 call 活跃的 value 可以：

- 放入 callee-saved register；
- 在 call 前 spill、call 后 reload；
- 在 call 两侧 split 到不同 registers；
- 若可重物化，在 call 后重新计算；
- 若有精确 [[RegMask]]，使用 callee 实际不会破坏的 register。

对于递归调用，callee clobber set 可能依赖函数自身的分配结果。一种方法是从保守或空假设开始，反复扩大 reg mask 到 fixed point。该过程必须单调，否则可能发生分配结果振荡。

## 9. Coalescing

Copy：

```text
v2 = copy v1
```

若 `v1`、`v2` 不 interference，可以分到同一物理寄存器，copy 随之消失。

激进 coalescing 的风险是把两个较短 live ranges 合并成长 range，增加与其他 values 的冲突，最终导致更多 spill。常见策略包括：

- conservative coalescing；
- optimistic coalescing；
- 把 copy relation 作为 hint，而非预先强制合并；
- 根据 block frequency 判断消除 copy 是否值得。

Phi coalescing 也需要 edge-aware liveness；不能把不同 predecessor 的 incoming values 错误视为同时活跃。

## 10. Priority 与 Cost

Greedy allocator 需要决定先分配谁。Priority 常考虑：

- live range 长度；
- use/def 数量；
- loop depth；
- block frequency；
- register class 稀缺程度；
- 是否跨 call；
- spill/reload 成本；
- rematerialization 成本；
- split 后的局部热度。

动态成本比静态条数更重要。热循环中每轮一次 reload，可能比冷路径中的多条 moves 更昂贵。

## 11. Eviction

若当前 bundle 想使用的寄存器已被较低优先级 bundles 占用，可以 evict 它们：

1. 暂时撤销 victims 的分配；
2. 把当前 bundle 放入目标寄存器；
3. victims 重新进入队列。

Eviction 必须有严格成本和进度约束，否则可能出现：

- 两组 bundles 互相驱逐；
- requeue 次数爆炸；
- 编译时间不稳定；
- 局部最优选择破坏全局质量。

## 12. Live-Range Splitting

Splitting 让同一个 value 的不同区段使用不同 placement。

### Around a Call

```text
hot value in caller-saved reg
-> call 前 spill
-> call 后 reload
```

### Hot/Cold Region Split

热循环内保留寄存器，冷路径 spill，从动态成本上可能优于全程占用寄存器。

### Block/Edge Split

不同 CFG regions 选择不同 registers，在边上插 transition move。Critical edge 需要先拆分。

### Local Split

在单个 block 中的特定程序点改变位置。

Split 的难点不是切区间本身，而是保证每个 use/def 位置都有正确 value，并在所有 placement 边界插入必要 transition。

## 13. Spill

Spill 把 value 放到 stack slot，并在 use 前 reload、def 后 store。

Spill 成本包括：

- 动态 load/store；
- address calculation；
- 栈帧大小；
- scratch register 压力；
- memory bandwidth 与 cache；
- 对 instruction scheduling 的影响。

“无法分配就 spill 整个 value”通常质量较差。Splitting 允许只 spill 冲突严重的区段。

## 14. Rematerialization

如果 value 可以廉价、无副作用地重新计算，就可以不保存到内存：

- small constant；
- global address；
- frame/stack address；
- 简单立即数运算。

```text
reload from stack
```

替换为：

```text
recompute value
```

Rematerialization 用计算换内存，但仍可能增加 code size、scratch 压力和 issue slots。还需保证重算语义不依赖已变化的 operands，也不会引入 trap 或 observable effect。

## 15. Spill Slot Reuse

不同 spilled values 若 stack live ranges 不重叠，可以复用同一 stack slot，类似对栈槽做一次 coloring。

必须考虑：

- 所有 spill segments；
- Phi/edge parallel copies 暂时需要的 source value；
- split transitions；
- alignment 和 size；
- 不同 register banks 的存取宽度；
- stack-to-stack copy 的临时需求。

若只看普通 instruction positions，可能在 edge copy 尚未读取旧值时过早复用栈槽。

## 16. Value Placement 与 Materialization

分配决策可以抽象为：

```text
InReg(register)
StackSpill(slot)
Remat(recipe)
```

某些架构还可能把 value 暂存在另一 register bank，但这种“parking”是否优于内存 spill 取决于跨 bank move 成本和微架构行为。

Materialization 根据每个 segment 的 placement：

- 把 virtual operands 改成 physical registers；
- 插入 spill/reload/remat；
- 处理 call arguments 和 returns；
- 在 local/edge split 边界插 moves；
- 消除 Phi/Upsilon 等 SSA 结构；
- 确保不再遗留 virtual values。

Planner 与 materializer 分离有助于保持“先确定全局位置，再一次性修改机器 IR”的清晰边界。

## 17. Parallel Move

Phi elimination、函数参数布局和 split transitions 可能产生平行复制：

```text
A0 <- A1
A1 <- A0
```

顺序执行会覆盖旧 `A0`。需要临时位置打破环：

```text
tmp <- A0
A0  <- A1
A1  <- tmp
```

Parallel move resolver 还要处理：

- register → register；
- register → stack；
- stack → register；
- stack → stack；
- rematerialized source；
- 不同 register banks；
- scratch 本身不能覆盖仍待使用的位置。

## 18. 寄存器压力与前序优化

前序优化会改变 RA 难度：

- LICM 把 value 提到 preheader，可能延长 live range；
- GVN/FRE 复用较早 definition，可能减少计算但增加干涉；
- aggressive inlining 增大函数和同时活跃值集合；
- unrolling 增加独立 temporaries；
- LSR 新增 pointer recurrences；
- instruction selection 的 addressing mode 可以减少临时地址 registers。

因此不能只用 IR instruction count 衡量优化收益。详见 [[GVN、FRE 与 PRE]] 和 [[指令选择与合法化]]。

## 19. 常见错误

- 把带 holes 的 value 当成一个连续大区间。
- 忽略 Phi uses 位于 edges。
- 把 hint 当成 fixed constraint。
- 没有建模 call clobber，导致跨 call value 被覆盖。
- Split 后没有在所有边界插 transition。
- Critical edge 上的 move 放到错误 block。
- Parallel copy 按顺序执行，破坏交换环。
- Spill slot 在 edge use 结束前被复用。
- Rematerialization 重算了可能 trap 或依赖变化状态的表达式。
- 只优化静态 move 数，不看热路径 spill。
- 分配完成后仍引入新的 virtual register。

## 20. 关系速记

```text
Machine SSA
  -> liveness
  -> live segments / bundles
  -> fixed constraints + hints + [[RegMask]]
  -> free register / evict / split / spill / remat
  -> placements + transitions
  -> parallel moves / Phi elimination
  -> physical-register machine IR
```
